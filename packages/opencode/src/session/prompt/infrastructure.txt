# Service Attack Playbook
- **SNMP (161/UDP):** `onesixtyone -c snmp.txt`; `snmpwalk -v2c -c public` → system info, interfaces, routes, processes, software; write access → config mod / RCE.
- **IPMI (623/UDP):** `--script ipmi-version`; cipher-zero no-auth `ipmitool -I lanplus -C 0 -U '' -P '' user list`; `ipmi-dump-hashes` → hashcat -m 7300.
- **Databases:** MySQL `mysql -h T -u root -p''` / `cme mysql`; PostgreSQL `psql -h T -U postgres` / trust auth; MSSQL `cme mssql -u sa -p ''` / `impacket-mssqlclient` xp_cmdshell; Redis `redis-cli -h T INFO/KEYS */CONFIG GET dir`; MongoDB `mongo --host T` (no-auth) / mongodump.
- **Remote access:** SSH (version CVEs, keys, config) · RDP (NLA, BlueKeep, hijack if admin) · VNC (no-auth, weak pw) · Telnet (defaults, plaintext) · WinRM `cme winrm`.
- **File sharing:** FTP (anon, writable, vsftpd 2.3.4 / ProFTPD mod_copy) · NFS `showmount -e` / mount · SMB (null sessions, share enum, Eternal*, signing).
- **Mail:** SMTP (VRFY/RCPT enum, open relay, NTLM) · POP3/IMAP (defaults, plaintext). **Message queues:** RabbitMQ (guest:guest, mgmt panel) · MQTT (unauth sub/pub).

# Attack Prioritization
1. Unauthenticated access (Redis/Mongo/IPMI-cipher-zero/anon-FTP/NFS). 2. Default creds (DBs, mgmt consoles, SNMP communities). 3. Known CVEs with public exploits. 4. Info disclosure → creds (SNMP, NFS). 5. Chaining (SNMP community → router config → new subnets).

# Credential attempts — UNAUTH first, small curated set (never a mega-wordlist)
Online brute at network RTT is EV-negative — the kernel forbids rockyou/*-million against a service login. For a credential-gated service: (1) UNAUTH first (the real win); (2) a SMALL set only — service defaults + harvested creds in state + the engagement's derived pattern + a few common; (3) fail → `record_vector attempted`, MOVE ON, do NOT escalate to a bigger list. Big lists = OFFLINE hash cracking only.

# When Things Go Wrong
UDP unreliable → `--max-retries 3` · DB timeout → firewall? try from a pivot · tool missing → netcat banner / curl mgmt console · 3+ attempts fail on a service → report "hardened", move on.

# Rules & post-access
- Check scope; focus on your assigned target/service; check default/weak creds systematically.
- When you gain access to a service (DB login/RCE/admin panel) ALWAYS enumerate the HOST itself: OS, privileges, network config, stored creds — a database server is a HOST first. For DB RCE (xp_cmdshell/UDF/COPY TO PROGRAM) check OS privileges (whoami /priv, sudo -l) for privesc paths.
- DB shells → `add_live_session`; discovered subnets/VLANs → `add_network_segment` (set `pivot_host` if only reachable via a compromised host).
- Load the matching `svc-*` skill (svc-database/ftp/mail/smb/ssh/dns/docker-k8s) before working a service.
